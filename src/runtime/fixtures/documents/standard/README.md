# Complete public document fixtures

These independently authored synthetic files contain only the public text in `inputs.json`.
`sample.*` covers installation acceptance; `eval/*` supplies the unchanged seven project notes
used by both document eval tasks. The minimal packages in `../../document-fixtures.ts` remain
separate boundary-test inputs.

PDF is generated by ReportLab; DOCX, XLSX and PPTX by the complete default package writers in
python-docx, openpyxl and python-pptx. LibreOffice imports complete OOXML seeds and saves ODT,
ODS and ODP. The fixtures retain root relationships, styles, themes, linked slides and ODF
manifests. These are application-produced documents, not hand-assembled parser fragments.

`manifest.json` records every SHA-256, byte size, expected text and exact generator/reader
version. Generation used Python 3.12.14 and the locally bundled tools; no network/model or
private document was used. LibreOffice's recorded development build is a fixture generator,
not a product dependency or a claim of exhaustive Office compatibility.

To regenerate with those recorded versions available:

```sh
python3 generate.py --soffice /path/to/soffice
python3 generate.py --soffice /path/to/soffice --verify
python3 generate.py --soffice /path/to/soffice --output /temporary/reproduction
```

The script checks pinned versions. Each LibreOffice invocation uses a new disposable profile
and a fresh environment; it never opens the user's Office profile. Creation/modification
times, authors, ZIP ordering/timestamps/permissions and LibreOffice revision identifiers are
fixed. Regeneration is byte-for-byte reproducible with the recorded toolchain on the same
platform; compression/font/application differences on other versions or platforms may change
bytes, so the committed hashes are authoritative.

Every generation verifies ZIP CRCs, XML syntax, all internal OOXML relationship targets and
ODF manifest entries. It checks uncompressed parts for local-user/private paths. PDF is reopened
with pypdf in strict mode; OOXML is reopened by its mature Python reader; each ODF file is
reopened by LibreOffice, exported to OOXML and read again with the corresponding Python reader.
These checks establish readable complete containers and exact text, not visual-layout fidelity.

Generator sources: [python-docx](https://github.com/python-openxml/python-docx),
[openpyxl](https://foss.heptapod.net/openpyxl/openpyxl),
[python-pptx](https://github.com/scanny/python-pptx),
[ReportLab](https://www.reportlab.com/), [LibreOffice](https://www.libreoffice.org/).
Verification also uses [pypdf](https://github.com/py-pdf/pypdf) and
[lxml](https://github.com/lxml/lxml); exact versions and the LibreOffice source revision are in
the manifest. No third-party document content is copied.
