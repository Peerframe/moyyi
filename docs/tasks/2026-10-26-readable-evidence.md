Owner 要求继续查 GitHub 的实际方案并完成产品优化。上一轮固定多题结果仍按失败保留；
本轮从运行产品修复源码呈现和预算阶段反馈，不修改原题、源码快照、六项标准或公共 checker。
继续现有 `codex/evidence-grounding` / PR #25；不叠 PR、不自动合并、不公开发布。

## GitHub 依据与实施

[ADR 0026](../decisions/0026-readable-evidence-and-action-budget.md)固定 OpenCode、Goose、Aider
的源码版本、许可、文件与测试。采用 OpenCode 的直接编号源码、独立元数据和续读语义。
Goose 完成 hook 与 Aider 客观检查反馈作为边界参考：它们不能判断任意事实，也不能在工具
额度耗尽后补写产物。本轮不引入要求用户另行配置、又不能修复当前语义错误的通用 hook。
没有复制上游代码或提示词，没有新依赖或外部框架。

1. **源码直接可读。** fs `read` 返回元数据与编号原文两个 text parts；源码只出现一次，
   原始 CRLF、Unicode、无结尾换行都保留。窗口完整不冒充全文完整，部分末行可重新读取，
   展示裁剪不保留错误行号。所有输出仍受原序列化字节上限约束。
2. **供应商使用原生文本。** DeepSeek 将工具结果映射为原生 `input_text` 数组，第一段明确
   工具状态，随后保留每段原文。不再把整个工具内容包成另一层 JSON 字符串。官方接口支持
   这一格式；不让 provider 猜测/解包任意工具 JSON。
3. **明确可执行机会。** 每轮预算 notice 区分总请求和还能用工具的请求；倒数第二次明确是
   最后工具机会，要求实际完成仍需工具的产物和检查。最终 `none`、零额外请求、权限和取消
   规则不变，不以答复里有 JSON 冒充文件已创建。
4. **录制可追溯。** 当前 API profile 升为 `deepseek-responses-text-v2-2026-10-26`，保留档位
   后缀与默认 high；本机继续显式 low。旧录制不改写，不得把 v1 冒充 v2；不匹配在执行前
   拒绝且无网络回退。persisted v1 和现有会话原文不变。
