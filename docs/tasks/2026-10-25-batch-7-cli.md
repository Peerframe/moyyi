## Delivered behavior

- A real terminal client uses the runtime protocol for session create/resume, streaming text,
  digest-bound explicit approvals, steering, Ctrl-C cancellation and EOF/exit cleanup.
  It escapes terminal controls/bidirectional text and does not execute printed content.
- One-shot prompts and bounded piped input use the same runtime. Unattended approvals are denied.
  The offline `--demo` is a finite existing scripted provider driving real README reads and SQLite;
  it is explicitly labeled and never presented as an LLM.
- `--host FILE` loads only an explicit trusted local RuntimeOptions module, retaining batch 6's
  credential callback. No environment credential fallback, keychain backend, workspace config or
  plugin discovery is added. Default file permissions and read-only policy remain in runtime.
- Explicit development plugins use `plugin.reload`/`plugin.status`. Busy reloads are rejected
  without unloading; idle admission is atomic. Unload precedes import/setup, then core bindings are
  rebuilt with the same store/session/policy. A failed plugin remains unloaded, and an unavailable
  selected provider blocks new runs until repair.
- Directory watching handles entry atomic replacement, coalesces changes and waits for idle.
  Manual `/reload` is the fallback. Only explicit `.mjs`/`.mts` ESM entries reload; imported static
  dependencies need restart. Development reload and recording/replay are mutually exclusive.
- Independent review fixed three reproduced blockers: raw reload errors exposed a synthetic
  secret; re-registering the same provider object reused its disposed client; an automatic-reload
  rejection could make `/resume` restore the wrong prior session. Regression tests and original
  probe retests now pass. No unresolved current blocker was reported.
