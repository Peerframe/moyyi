## 现在从哪里开始

[系统总览](../system-overview.md)是唯一的当前工程决策入口。它把以下内容串在同一页：

1. 产品目标与用户任务，不以测试数或阶段数代替能用程度。
2. CLI、host、runtime、core、context、provider、工具、权限和存储的完整路径。
3. 合并主线、未合并候选、本机安装版、真实验收结果的区别。
4. 每类用户任务已有的能力、证据、限制与代码负责人。
5. 当前问题在哪一层、下一项完整成果及何时停止沿错误层面修补。

README、贡献者入口、架构、路线图和旧任务书都导向它。架构继续管层与契约，路线图管后续方向，
任务书保留当时的验收事实；不再让过时的“当前分支”“尚未连接”“PR待审”决定下一步。
也修正了评测说明中“默认加载私有题”的错误；实际需要显式 `--include-private`。

## 整体判断

底层执行、安全、存储、安装能力已经存在。现在的主要缺口是“能否可靠完成用户任务”的工程闭环，
包括工具接口、证据覆盖、模型解释与答案，以及真正衡量这些行为的多题评测。
因此不重写核心、不急着加GUI/更多模型，也不把所有问题都归因于搜索。

[上游研究](../research/2026-10-26-agent-navigation.md)核对了Codex、OpenCode、Aider、SWE-agent和mini的
固定源码、许可证、代表测试与公开实验。没有搬用上游Agent内核，也没有把文档宣称当成实测。
本机四个合成探针复现单文件搜索、文件过滤、文件发现与参数错误反馈的具体差距；零模型请求。

下一项产品成果是完整、相互配合的调查工具接口，再用现有任务框架衡量整个任务：
精确文件/目录、显式过滤、先找文件或直接取内容、可操作错误、真实范围/省略标记。
保留原安全边界、Flash + Responses + low和原题全部标准。
结构索引/LSP留待有证据证明仍需要时；图和计划状态本身不能证明结论正确。
产品实现及新增真实多题测试不在本轮文档交付中，既有8次预算已耗尽，不自动续跑。
